Microsoft Bug Demo — Null Dereference

NullReferenceException Open System.Xml.Serialization
dotnet/runtime#120561 →

💥 What's the Bug?

In the .NET runtime's XML serialization code, reflection is used to look up ShouldSerialize{PropertyName}() methods on objects. The lookup uses BindingFlags.DeclaredOnly, which only searches the exact runtime type — it does not walk up the inheritance chain. When the method is defined on a base class and a derived class instance is being serialized, GetMethod() returns null and the subsequent .Invoke() call throws a NullReferenceException.

🔍 Root Cause

Here's the buggy code, distilled into a minimal reproducer:

public static bool CheckShouldPersist(object o, string memberName)
{
    string methodInvoke = $"ShouldSerialize{memberName}";

    MethodInfo method = o.GetType().GetMethod(
        methodInvoke,
        BindingFlags.Public | BindingFlags.NonPublic
        | BindingFlags.Instance | BindingFlags.Static
        | BindingFlags.DeclaredOnly)!;  // ← BUG: skips base class methods
    bool shouldPersist = (bool)method.Invoke(o, Array.Empty<object>())!;  // ← NullReferenceException!

    return shouldPersist;
}
⚠️

BindingFlags.DeclaredOnly restricts reflection to methods declared directly on the queried type. Inherited methods from base classes are invisible. When the method lives on a parent class, GetMethod() returns null.

🏗️ How Inheritance Breaks It

🧪 Test Results

Three tests demonstrate the exact failure boundary:

Test Object Type Looking For Method Defined On Result
Same class method Test ShouldSerializeTestProp Test ✓ Pass
Base instance, base method TestBase ShouldSerializeBaseProp TestBase ✓ Pass
Derived instance, base method Test ShouldSerializeBaseProp TestBase ✗ NullReferenceException

The first two pass because the method happens to be on the exact type queried. The third fails because the method is inherited from a base class, and DeclaredOnly refuses to look there.

📋 Step-by-Step Failure

  1. Serializer encounters a derived object
    An object of type Test (which extends TestBase) is being serialized.
  2. Checks for ShouldSerialize method
    For the property BaseProp, it constructs the method name "ShouldSerializeBaseProp".
  3. Reflection lookup with DeclaredOnly
    typeof(Test).GetMethod("ShouldSerializeBaseProp", ... | DeclaredOnly) only searches methods declared directly on Test.
  4. GetMethod returns null
    The method is defined on TestBase, not on Test. The search finds nothing.
  5. NullReferenceException on .Invoke()
    The code calls method.Invoke(o, ...) on a null reference — crash.

✅ How to Fix It

Remove BindingFlags.DeclaredOnly so the reflection search walks the full inheritance chain, or manually traverse the type hierarchy. Here's the simplest fix: 

public static bool CheckShouldPersist(object o, string memberName)
{
    string methodInvoke = $"ShouldSerialize{memberName}";

    MethodInfo? method = o.GetType().GetMethod(
        methodInvoke,
        BindingFlags.Public | BindingFlags.NonPublic
        | BindingFlags.Instance | BindingFlags.Static);  // ✓ No DeclaredOnly — searches base classes too

    if (method == null)
        return true;  // default: persist if no ShouldSerialize method found

    return (bool)method.Invoke(o, Array.Empty<object>())!;
}
✅

Fix: Removing BindingFlags.DeclaredOnly lets GetMethod() traverse the full type hierarchy, finding inherited ShouldSerialize* methods on base classes. Adding a null check prevents the crash even if no method exists at all.

🌍 Real-World Impact

💥 XML Serialization Crashes

Any class hierarchy using ShouldSerialize patterns (common in WinForms, WPF, and data-binding scenarios) can crash during XML serialization if the method is declared on a base class.

🔍 Hard to Diagnose

The NullReferenceException stack trace points into framework internals, not user code. Developers may not realize the root cause is a missing BindingFlags in the runtime.

🎯 Specific Trigger

Only triggers when: (1) using XML serialization, (2) with class inheritance, and (3) a ShouldSerialize* method is on a base class. Works fine when everything is on one class.

🛠️ Source Location

The bug lives in ReflectionXmlSerializationWriter.cs in the System.Private.Xml assembly of the .NET runtime.
