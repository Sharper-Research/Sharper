COMMIT: Alias resolution + remove throw regression
======================================================
Last commit ("Log array aliases and asserts") added alias tracing
but also added Debug.Fail() + throw, in catch blocks. That throw killed
the program on the first crash, so RunLoop2 and buf1[buf1.Length] never
ran. We went from 4 violations before the ("Log array aliases and asserts") commit down to 1. 
This commmit also wires up the alias data so Step 2 can actually use it.

AFTER  ("Alias resolution + remove throw regression"): 6 violations detected

  3  BufferBoundsRule  Worker.cs     26    buf2 OOB (proactive, via alias) THIS WAS MISSING (It was not detected)

  6  ExceptionRule     Program.cs    7     buf1[buf1.Length] crash

"buf2" passed as "buffer" to RunLoop2, StateTracker resolves buffer -> buf2 -> size 8 -> index 11 is OOB.


WHAT I CHANGED AND WHERE
-------------------------
1. SafetyRewriter.cs (Step1_Tracing/Instrumenter/Rewriters/)
   - Removed Debug.Fail() and throw; from CreateExceptionCatchLogs()
   - Removed unused "using System.Diagnostics;"
   
   - The "throw" re-threw caught exceptions, killing the program
     on the first crash. The rest of the bugs were never reached.

2. ControlFlowRewriter.cs (Step1_Tracing/Instrumenter/Rewriters/)
   - Removed VisitInvocationExpression() override (dead code, every
     branch returned visited unchanged, did nothing)
   - Added "Debug." to the filter in CreateArrayArgumentLogs() so
     Debug.Fail() calls don't produce spurious alias events
   
   - The override was a no-op and Debug.Fail alias events were noise in the trace.

3. StateTracker.cs (Step2_Constraints/Constraints/Runtime/)
   - Added _paramToArgAlias dictionary (maps param name -> caller arg name)
   - Added _argumentAliasCache dictionary (temp store for alias keys)
   - Update() now processes "Array Argument Alias" and "Array Parameter Alias"
     events to build the mapping: buffer -> buf2
   - TryGetBufferSize() now falls through to alias lookup when direct lookup fails
   
   - Without this, BufferBoundsRule could never find the size of "buffer" 
     because only "buf2" was in the heap table.


HOW THE ALIAS WORKS (simple version)
-------------------------------------
Caller:  Worker.RunLoop2(buf2, 11)
  -> trace emits: "Array Argument Alias" name=RunLoop2#arg0 val=buf2

Callee:  public static void RunLoop2(int[] buffer, ...)
  -> trace emits: "Array Parameter Alias" name=RunLoop2#arg0 val=buffer

StateTracker matches on "RunLoop2#arg0" and stores: buffer -> buf2
Later when index:buffer = 11, BufferBoundsRule asks for size of "buffer",
StateTracker looks up buffer -> buf2 -> size 8 -> violation.
